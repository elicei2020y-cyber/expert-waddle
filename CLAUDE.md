# CLAUDE.md — инструкция для Claude Code

Читай целиком до любых действий. Здесь правила, без которых результат не
засчитывается.

## 1. Кто что делает

- **Автор проекта** ставит цель и принимает решения.
- **Главный мозг** (отдельный Claude, работает с автором вне этого
  репозитория) составил задание, записал предсказания и проверяет твои
  отчёты. Твои отчёты попадают к нему через автора.
- **Ты** выполняешь задание в этом репозитории: пишешь код, гоняешь
  опыты, пишешь отчёт. Выводы о смысле результатов — осторожно, только
  то, что следует из чисел.

## 2. Что это за проект — коротко

**Симбиоз** — архитектура, где проверяющий код читает выдачу языковой
модели по мере порождения. Найдя дефект, он **отматывает** порождение
назад, до места, где дефект возник, и перепорождает с **пометкой**: что
отозвано и почему.

До сих пор это мерилось только на **игрушке** — маленькой символьной
модели (`igrushka/`). Результаты игрушки описаны в
`docs/igrushka_rezultaty.md`. Коротко: отмотка ничего не портит, почти
ничего не спасает и переводит ошибки в молчание. Пометка в игрушке —
весь механизм, но игрушка её не «понимает», пометка лишь меняет контекст.

**Твоя задача (`ZADANIE.md`)** — повторить опыт на настоящей языковой
модели, которая пометку прочитать может.

## 3. Дисциплина — обязательно

1. **Предсказания до прогона.** Они уже записаны в `PREDICTIONS.md`.
   Не правь их. После прогона заполни табель: сбылось / не сбылось, с
   числами.
2. **Отрицательный результат — полноценный результат.** Не подгоняй
   условия, пока предсказание не «сбудется». Если механизм не работает,
   так и пиши первой строкой отчёта.
3. **Цифры, а не прилагательные.** Не «заметно лучше», а «22 против 38».
4. **Соперник обязателен.** У каждого механизма должен быть соперник с
   тем же бюджетом, но без механизма (в задании это политика Д). Без
   соперника результат не засчитывается.
5. **Контрольные точки.** После этапа 0 (установка и проба скорости)
   **остановись** и отчитайся: сколько секунд на отчёт, сколько займёт
   полный прогон. Дальше — только после ответа автора.

## 4. Ловушки, в которые уже попадали

- **Одно число из одного прогона.** Там, где есть случайность
  (семплирование), минимум 5 зёрен, отчитывайся средним и разбросом.
- **Лишняя работа маскирует пользу.** Если механизм ухудшает результат,
  сначала ищи лишнюю работу (лишние перепорождения, повторные вызовы),
  потом делай выводы.
- **Счётчик, считающий повторы.** Считай уникальные отчёты и поля, а не
  события.
- **Кредит за чужую работу.** Если модель и так отвечает верно,
  отмотка тут ни при чём. Спасённым считается только то, что БЫЛО
  неверно и СТАЛО верно.
- **Стенд сломан, а не механизм.** Если отмотка без пометки при жадном
  декодировании даёт не тот же знак в знак результат, что и
  «не вмешиваться», — сломан стенд. Чини стенд до выводов.

## 5. Чего не делать

- Не класть веса модели и квантованные копии в git (см. `.gitignore`).
- Не называть результат «исправлением галлюцинаций» или «разумом». Это
  арифметическая задача со строгой проверкой.
- Не менять игрушку в `igrushka/`: это эталон для сравнения.
  `python3 igrushka/proverka.py` должен давать «совпало».
- Не ставить `pip install torch` без адреса CPU-сборки: иначе скачаются
  гигабайты библиотек для видеокарт, которых здесь нет.

## 6. Как запускать

```bash
pip install -r requirements.txt
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install transformers
python3 igrushka/proverka.py        # эталон игрушки, ждём «совпало»
```

Машина: 4 ядра, 15 ГБ памяти, без видеокарты, ~30 ГБ диска на сессию.
